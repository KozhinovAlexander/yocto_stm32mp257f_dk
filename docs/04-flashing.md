# 04 – Flashing

This guide covers flashing the built image onto the STM32MP257F-DK board using
an SD card or eMMC, and accessing the board over the serial console.

---

## Boot Mode Selection (DIP Switches)

The STM32MP257F-DK uses DIP switches (SW1) to select the boot source.

| Mode | SW1-1 | SW1-2 | SW1-3 | SW1-4 | Description |
|------|-------|-------|-------|-------|-------------|
| Engineering / DFU | ON  | OFF | OFF | OFF | USB DFU boot (for initial programming) |
| SD Card | OFF | ON  | OFF | OFF | Boot from microSD slot |
| eMMC | OFF | OFF | ON  | OFF | Boot from on-board eMMC |

> Consult the [STM32MP257F-DK user manual](https://www.st.com/resource/en/user_manual/dm00838073.pdf)
> for the exact switch positions on your board revision.

---

## Flash to SD Card

### Prerequisites

- A microSD card (≥ 8 GB recommended)
- The compressed WIC image from `build/tmp/deploy/images/stm32mp257f-dk/`

### Steps

```bash
# Identify your SD card device (e.g., /dev/sdb or /dev/mmcblk0)
lsblk

# Decompress and write the image (replace /dev/sdX with your device)
xzcat stm32mp257f-image-minimal-stm32mp257f-dk.rootfs.wic.xz | \
    sudo dd of=/dev/sdX bs=4M conv=fsync status=progress

sudo sync
```

> **WARNING:** Replace `/dev/sdX` with the correct device path.
> Writing to the wrong device will destroy data.

Set the DIP switches to **SD Card** mode, insert the SD card, and power on.

## Flash to eMMC via STM32CubeProgrammer

For production or faster boot times, flash the image directly to the eMMC.

### Prerequisites

1. Install [STM32CubeProgrammer](https://www.st.com/en/development-tools/stm32cubeprog.html)
   (v2.14 or later).
2. Connect a USB Type-C cable between the board's USB-C OTG port and your host.

### Steps

```bash
# Set DIP switches to Engineering / DFU mode, then power on the board.

# Locate the flashlayout file (generated by the build)
DEPLOY=build/tmp/deploy/images/stm32mp257f-dk
LAYOUT=$(ls ${DEPLOY}/flashlayout_stm32mp257f-image-minimal/FlashLayout_emmc_*.tsv | head -1)

# Flash using STM32CubeProgrammer CLI
STM32_Programmer_CLI \
  -c port=usb1 \
  -w "${LAYOUT}" \
  -v \
  --download "${DEPLOY}"
```

STM32CubeProgrammer reads the TSV flashlayout and automatically programs all
partitions (TF-A, FIP, kernel, rootfs) in the correct order.

After flashing, set the DIP switches to **eMMC** mode and power cycle the board.

## Serial Console

The STM32MP257F-DK exposes a UART console on the **UART4 / CN14** connector.

### Pinout (CN14 – 3-pin header)

| Pin | Signal | Direction |
|-----|--------|-----------|
| 1   | GND    | –         |
| 2   | UART4_TX | Board → Host |
| 3   | UART4_RX | Host → Board |

Connect a USB-to-UART adapter (3.3 V logic, e.g. FTDI FT232R or CP2102):

```
Adapter GND  ──►  CN14 Pin 1 (GND)
Adapter RX   ──►  CN14 Pin 2 (TX)
Adapter TX   ──►  CN14 Pin 3 (RX)
```

### Open a Terminal

```bash
# Using minicom
sudo minicom -D /dev/ttyUSB0 -b 115200

# Using screen
sudo screen /dev/ttyUSB0 115200

# Using picocom
sudo picocom -b 115200 /dev/ttyUSB0
```

Serial settings: **115200 8N1, no hardware flow control**.

## SSH Access After First Boot

With `debug-tweaks` enabled, the root password is empty. Connect the board to
your network via Ethernet and find its IP address from the serial console:

```bash
# On the board's serial console:
ip addr show eth0

# From your host:
ssh root@<board-ip-address>
```

## Partial Update – Kernel Only

To update only the kernel without reflashing the entire image:

```bash
# Build only the kernel
bitbake virtual/kernel

# Copy the new kernel and DTB to the board
scp build/tmp/deploy/images/stm32mp257f-dk/Image \
    root@<board-ip>:/boot/

scp build/tmp/deploy/images/stm32mp257f-dk/stm32mp257f-dk.dtb \
    root@<board-ip>:/boot/

# Reboot the board
ssh root@<board-ip> reboot
```

Alternatively, use STM32CubeProgrammer to write only the `bootfs` partition with
the updated kernel.
